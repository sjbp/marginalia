# Decisions log

One line each, newest first. Defaults from SPEC §3 unless noted.

- 2026-10-18 Google Fonts' build of Google Sans Flex has no `GRAD` axis (axes: opsz, wdth, wght, ROND, slnt). Dark mode compensates with +40 weight on every theme instead.
- 2026-10-18 CLI finds the app relative to its own binary (`Marginalia.app/Contents/MacOS/md`), so `~/.local/bin/md` is a symlink into the bundle. No bundle-id lookup needed, works for dev builds too.
- 2026-10-18 Swift tools 5.10, language mode 5. Strict concurrency of Swift 6 mode adds nothing for a single-window AppKit app and costs hours.
- 2026-10-19 TextKit 2 geometry: fragment frames and `firstRect(forCharacterRange:)` are estimates for text outside the viewport and drift after display passes. Programmatic scrolling therefore (1) brings the range into view with `scrollRangeToVisible`, (2) verifies visibility by hit test (`characterIndexForInsertion`), (3) aligns with the on-screen rect, and (4) re-checks at 20/80/200/450/800 ms. Only user gestures cancel the re-checks.
- 2026-10-19 Modified lines show only the green bar. A red deletion rule appears only for pure removals, so a replaced line is not double-marked.
- 2026-10-19 Change bars sit at the far left of the column (not next to the text edge) so they never collide with hanging `######` markers.
- 2026-10-19 Edit-script mode manages undo groups per step because no real events flow, so event-based grouping never closes.
- 2026-10-19 Reading mode keeps one NSTextView and one text storage. Syntax that should disappear is rendered in a 0.1 pt clear font (offsets never change, so cards, change bars, and scroll anchoring keep working). Tables and images reserve paragraph height and get native overlay views. Chosen over a second rendered attributed string because every other subsystem keys on source offsets.
- 2026-10-19 Outline (⌘⇧O) is the command palette in heading mode with the current section preselected, not a separate popover. One UI, same keyboard model.
- 2026-10-19 ⌘K is the palette, so Link moved to ⌘⇧K.
- 2026-10-19 Default window is 1180 pt wide when the screen allows, not 860 as the spec said, because margin cards need about 1040 pt and comments are the point of the app.
- 2026-10-19 Perf: card and overlay positioning is gated to the viewport range ± 12k characters. Positioning a far anchor forces TextKit 2 to lay out everything before it, which was the single largest cost on large files.
- 2026-10-19 Perf: NSTextStorage.string is a bridged NSString; `makeContiguousUTF8()` once per parse or reload makes the diff and parser 5 to 10× faster.
- 2026-10-19 Perf: styling is applied to the visible region first and the rest in 600-line slices above 800 lines; parsing moves to a background queue above 200 k characters. The main menu installs one turn after the first window.
- 2026-10-19 Feedback round 1: rendered text is the default and editable. The caret's block (line, or whole code block / table / frontmatter) reveals its Markdown, everything else stays rendered. ⌘⇧R shows the full source. The old read-only reading mode is gone.
- 2026-10-19 Comments are threads: adjacent `{>>…<<}` chain into one card with a reply box at the bottom. Resolve removes the whole thread and unwraps the highlight. A new comment is created empty and the first text fills it.
- 2026-10-19 Selecting text shows a small "Comment ⌘⇧M" pill above the selection. Comment actions keep the viewport where it was (anchor + restore).
- 2026-10-19 Comment tint is the accent at 11% (light) / 20% (dark), comment source text is muted gray. The gold highlighter is gone.
- 2026-10-19 On-screen rect measurements use the whole line range, because a line's first characters can be hidden runs whose rect is not the line's top.
- 2026-10-19 Feedback round 2: no Markdown reveal under the caret (it moved content on click). Rendered text is always rendered, with a Text | Markdown toggle bottom-right and ⌘⇧R. Hidden syntax is handled by behavior instead: arrow keys move one visible character (markers are skipped, direction decides which side of a marker the caret lands on), backspace or forward-delete on a marker unwraps the whole span, backspace at the start of a list item or heading drops the prefix, the caret never rests inside a hidden run.
- 2026-10-19 The selection pill is replaced by a floating format bar (heading menu, bold, italic, strike, code, link, bullet, numbered, task, quote, comment). It shows on mouse-up or keyboard selection, hides on click, text change, empty selection, or focus loss, and stays attached after a formatting action.
- 2026-10-19 Click a checkbox in the gutter to toggle it. Paste a URL over a selection to make a link. Double-click a table or image to edit it as Markdown. Empty files show "Start writing…". Windows show the folder as a subtitle. App icon: a plain circle with two margin bars (first version, later replaced by the text-column mark).
- 2026-10-19 Design review round (gstack design-review, adapted to a native app: screenshots stand in for pages). Selection is drawn by the app on text extents; AppKit's pass is silenced through the private `_selectionBackgroundColor` override, a deliberate private-API use for a personal app. List markers share one right edge 10 pt before the text and center on the x-height from the layout fragment's baseline. Code panels are one width (the column) and long lines wrap; hidden fences are the panel's inner padding. A commented document is left-biased (left margin capped at 112 pt) and cards widen to 360 pt. Format bar buttons have hover and pressed fills.
- 2026-10-19 Typography moodboard published as an artifact (Marginalia Type Board) with 19 OFL directions; decision pending Sebastián's picks.
- 2026-10-19 Typography decided from the type board and the Geist Scale Explorer: Geist + Geist Mono is the default theme ("Recommended" preset): H1 2.1×, H2 1.55×, H3 1.2× of a 17 px body at weight 600, tracking −0.025 / −0.015 / −0.005 em, heading line height 1.1 (H3 1.2), more air above H2 and H3. Flex, Newsreader and Quattro stay as alternates. Saved preferences migrate to Geist once (key themeMigratedToGeist).
- 2026-10-19 Floating views (thread cards, table and image overlays) are positioned in the text view's viewWillDraw after a forced viewport layout, not right after styling. Styling runs before TextKit reflows, so positions computed then are stale whenever an edit changes line counts above. Frames are only written when they change.
- 2026-10-19 Root cause of overlays and cards drifting while typing: every keystroke restyled the whole document, which invalidated TextKit 2 layout for the whole file; floating views were then placed from estimated positions and nothing corrected them. Fixes: (1) incremental restyle, only lines whose signature (kind, depth, prefix, flags, reserved height) changed, aligned by index around the edit; (2) overlays are reused across edits and only rebuilt when a table or image block's text changes; (3) before placing a floating view, layout is ensured contiguously from the viewport start to it; (4) typed characters take the attributes of their line so a heading never collapses for a frame. Regression: `make overlay-test` posts real key events and asserts placement after every keystroke on a short-window fixture and on tour.md at 1250×1350; env hooks MARGINALIA_FULL_RESTYLE and MARGINALIA_NO_ENSURE reproduce the old behaviour and fail the test.
